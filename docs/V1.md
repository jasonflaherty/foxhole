# Foxhole v1.0.0 definition

Product contract for tagging **v1.0.0**. Foxhole is an offline-first **workspace CI gate**, not a SaaS AppSec platform.

## What v1 is

One scan produces one findings list (`vuln | secret | eol | misconfig | license`).
CI decides with deterministic exit codes. Optional **evidence packs** and **air-gap DB
bundles** support auditors and disconnected runners.

## In scope (supported)

| Capability | Notes |
|------------|--------|
| Scan + policy gate | Exit `0` OK, `1` tool/stale DB, `2` policy fail |
| Reports | Console, JSON (`schema_version` envelope), SARIF, Markdown, HTML, JUnit, CycloneDX, SPDX, `--split-reports` |
| Evidence | `--evidence` → manifest, policy fingerprint, result, SARIF, suppressions |
| Air-gap | `db export` / `db import`, `--offline`, `--max-db-age` — see [AIRGAP.md](AIRGAP.md) |
| Secrets | Curated high-confidence regex pack (AWS/GCP/Azure/GitHub/JWT/PEM/…) |
| CI packaging | Jenkins examples, Actions demos, GHCR (+ optional Docker Hub), cosign as documented |

## Stability contract

For v1.x, treat as stable unless a major bump:

- Exit codes `0` / `1` / `2`
- Policy YAML fields (`fail_on`, `kinds`, `ignore`, `suppressions`, `id`, `version`)
- JSON report envelope (`schema_version`, `tool`, `result`)
- Evidence pack layout under `foxhole-evidence/`
- Primary CLI flags for scan, policy, evidence, and DB bundle flows

Breaking changes to those surfaces require **v2**.

## Out of scope (non-goals for v1)

- Multi-tenant SaaS, org dashboard, or scheduled cloud scans
- Reachability / call-graph analysis
- Live secret verification (`verified=true` API checks)
- Replacing Dependabot, Trivy (image/FS), or dedicated secret hunters (TruffleHog/Gitleaks)

## Known limits

- Vuln coverage depends on a fresh DB (`db update` or imported bundle)
- Secrets are pattern matches — JWTs in tests and similar noise can fire
- `foxhole serve` dashboard shows history stats, not a full per-finding UI

## Release bar for v1.0.0

- This definition is published and linked from the README
- `v0.4.x` soaked in real CI without contract-breaking surprises
- Tagged release + image; release notes state upgrade path from 0.3/0.4
- No new product lines required — prove the gate, don’t expand the platform
